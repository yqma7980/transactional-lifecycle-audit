# L5-D2 independent-validation contract

Status: `FROZEN_NOT_IMPLEMENTED`

Design version: `L5-D2.0`

## Independence boundary

L5-D2 is a protocol revision around the existing independently written L5 implementation. The L5-D1 implementation may be imported as a hash-protected immutable dependency. No L5-D1 file may be modified. New D2 behavior must be implemented in D2-named modules, tests and runner files and must write only to a D2 result root.

L5-D2 must not import or call any L4 solver, state class, flux/update routine, lifecycle variant, oracle, serializer, output projector or runner. It may read immutable L4 formal CSV/JSON data only for `L5-D2-XP-01` after verifying the frozen L4 raw aggregate hash.

## Immutable dependencies

- `src/l5_state.py`: independent records and binary serializer.
- `src/l5_solver.py`: MUSCL/Rusanov/SSPRK2 flow solver and output reconstruction.
- `src/l5_oracle.py`: independent entropy and fixed Gauss-8 reference.
- `src/l5_lifecycle.py`: independently written safe/unsafe transaction host.
- `src/l5_cases.py`: reusable D1 case helpers only where semantics are unchanged.

The D2 convergence case must not call the D1 three-level `_convergence` classifier. It must independently assemble five D1 solver/reference evaluations and classify them with the frozen D2 regression contract.

## Reference and state ownership

The exact reference remains independently implemented from the physical definitions and must not be generated by the L4 solver. Committed state is immutable; every trial begins from the declared committed state; rejected trial state cannot reach accepted output. The binary serializer remains the single authoritative L5 fingerprint source.

## Historical and formal evidence separation

L5-D1 precheck outputs and diagnostic extended levels are read-only historical evidence. They may be used to document the D2 rationale but may not be read by the D2 formal runner, copied into D2 results, or used as cached solver outputs. Every D2 formal run must recompute its fields in a fresh process.

## Claim boundary

A complete D2 pass may be labelled `OBSERVED-L5` for the frozen standalone one-dimensional benchmark. It is not external-host evidence, Abaqus evidence, production evidence, two-way-coupling validation or a performance result.
